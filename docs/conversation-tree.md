# 项目对话树与迁移（2.4.0）

需要 DSH 0.2.2-rc.3。主入口在 DSH 左侧的「项目对话树」，原来的 Codex 代管面板保留。

## 页面使用

1. 点击「项目对话树」，选择一个项目文件夹。页面读取 DSH 工作区、DSH 历史和 Codex 本地项目/历史；空项目也能显示。Codex 不可用时会显示错误，DSH 项目仍可使用。
2. 文件夹根深度为 0。「从 0 新开」创建空白 DSH 对话，深度为 1。
3. 点击对话查看完整历史。DSH 节点可双击或点击「进入 DSH 对话」直接聊天。
4. Codex 节点点击「迁移到 DSH 继续」；DSH 节点点击「新建分支」。填写标题和真实分支原因，创建后进入 DSH。新节点深度为父节点加 1。
5. 勾选「用 DeepSeek 总结分支原因」会消耗少量 DeepSeek 额度。树枝显示简短摘要；摘要失败不撤销已创建的对话，可稍后点击「DeepSeek 总结」重试。

项目级「自动用 DeepSeek 总结新分支」默认关闭。开启后，页面打开期间会逐条处理待总结分支，包括 Codex 通过共享文件登记的分支；失败的条目保留错误，不自动反复调用。关闭它不会追溯撤销已经开始的请求。

「同步两端」重新发现新增的历史；共享树文件的修改每 4 秒自动刷新。选中对话的历史每 5 秒读取一次，暂停或完成后仍刷新，不按 6000 字截断。

## 迁移语义

- Codex → DSH：分页读取全部可用历史，转换为 DSH 原生的已完成历史轮次。用户消息和助手正文保持文本，工具/推理等记录以标注后的文本保留；工具不会重新执行。完整来源 JSON 另存到项目的 `.dsh-codex-dots/history/`。
- DSH → DSH：直接进入现有对话，或调用宿主原生 fork 创建分支。正在执行的源对话应先结束或暂停，原生 fork 使用完整已保存历史的快照边界；纯空白对话创建空白子节点。
- 原始对话不删除。迁移/创建自身不派发新的模型任务；进入 DSH 后由用户发送下一条消息。分支摘要是独立的可选 DeepSeek 调用。
- 图片、文件与工具记录中的路径会保留；本版不复制附件二进制文件。附件需要继续使用时，在 DSH 重新附加。完整持久历史不等于单次模型请求可以超过模型的上下文窗口。
- Codex 原生 fork/subagent 的明确父 ID 会关联；DSH 的明确 parentSession 也会关联。没有明确父来源的旧 DSH fork 显示「来源待关联」，深度显示 `?`。可在「分支关系」中选择真实父节点或明确标记为从 0 新开，不能靠标题相似猜测。

## DSH 与 Codex 共建

共享数据位于每个项目的 `.dsh-codex-dots/tree.json`。它记录来源、对话 ID、父节点、分支意图、DeepSeek 摘要与修订号。深度由父子关系计算；两端写入使用短时文件锁和原子替换，合并其他端的最新修改。

DSH 通过页面或以下工具维护：

| 工具 | 用途 |
|---|---|
| `dots_projects` | 查询两端项目 |
| `dots_tree` | 同步项目中的对话与树 |
| `dots_conversation_read` | 读取完整对话历史 |
| `dots_conversation_create` | 新建、迁移或分支 DSH 对话 |
| `dots_tree_link` | 维护父子关系与分支意图 |
| `dots_branch_summary` | 经确认使用 DeepSeek 总结分支原因 |

Codex 使用随插件提供的无依赖 Node 命令。页面「与 Codex 共建此树」会显示本机脚本绝对路径和所选节点 key。以下路径是示例，替换为目标电脑实际路径：

```powershell
node 'C:/dsh-plugins/codex-dots/scripts/conversation-tree.mjs' list 'C:/my-project'

# 登记真实的新对话。写操作从 stdin 读取 JSON，避免路径和中文引号被 shell 误解。
@'
{"source":"codex","id":"实际子对话ID","title":"对比另一种方案","parentKey":"codex:实际父对话ID","intent":"保留当前实现，单独验证另一种方案"}
'@ | node 'C:/dsh-plugins/codex-dots/scripts/conversation-tree.mjs' register 'C:/my-project'

# 给已存在的节点补充父子关系。
@'
{"key":"dsh:实际子对话ID","parentKey":"codex:实际父对话ID","intent":"改用DeepSeek继续分析"}
'@ | node 'C:/dsh-plugins/codex-dots/scripts/conversation-tree.mjs' link 'C:/my-project'
```

CLI 只维护树，不创建伪造的 Codex 会话，不启动模型，也不会自动提高沙箱权限。应先有真实对话，再登记其 ID。只读 Codex 任务不能借维护树获得写权限；由 DSH 页面代为保存即可。完整历史目录包含本机对话内容，不随插件发行包发布。

## 手动验收

本版不使用 Computer Use、不自动重启 DSH，不自动进行付费联调。请在现有任务结束后手动重启 DSH，核对插件为 2.4.0、组件运行中，再按下面检查：

1. 打开「项目对话树」，确认能看到两端项目和对话，选择已有测试对话核对正文、Markdown 和代码颜色。
2. 新建一个空白 DSH 对话，确认深度 1；输入并完成一句测试消息。
3. 从它创建分支，填写「换一个角度检查结论」。若勾选摘要，确认费用提示后使用少量 DeepSeek 额度；核对深度 2、树枝摘要和跳转。
4. 再从该分支创建下一层，核对深度 3。父子关系错误时修改关系，确认不能形成循环。
5. 选一条已完成的 Codex 测试对话，取消摘要勾选后迁移。确认 DSH 原生聊天中出现历史，原 Codex 对话仍在；手动发送一条新消息验证接续。此新消息会消耗 DSH 模型额度。
6. 在 Codex 使用上面的 CLI 登记/关联真实节点。保持 DSH 树页面打开，核对 4 秒左右自动出现修改；再在 DSH 修改意图，用 CLI `list` 确认能读到。
7. 对旧代管测试对话进行已确认预算内的暂停/恢复；核对旧代管侧栏与新树历史都能刷新。不要为验收擅自降低额度阈值。

出现问题时提供操作步骤和完整错误文本。没有真实来源证据的旧 fork 保留待关联，不作为迁移失败。
