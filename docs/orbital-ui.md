# 对话星图（2.6.10）

需要 DSH 0.2.2-rc.3。本次仅更新本地，GitHub 保持已发布版本。

## 页面与同步

打开左侧「项目对话树」。Codex 项目为浅蓝紫色毛玻璃球，DSH 项目为浅薄荷色；同目录同时属于两端时沿用 Codex 颜色。项目球随机散布，按普通对话数量在 88–156px 内适度增大。悬停放大，点击项目在中央展开分层树，其余项目按平台分开：Codex 在左、DSH 在右。项目根深度 0，对话从 1 开始逐层递增。树按逐层轮廓紧凑排列，父球对齐直接子节点中点，项目根位于画布中轴。初次展开或分支结构改变时自动居中，普通内容刷新保留浏览位置；右上角“居中”可回到根球。大树支持横向、纵向滚动。

鼠标悬停对话球或其操作区时显示「分支」「历史」「Dots」「删除」小球。DSH 原生对话快速双击进入，无需先复制项目。Codex 对话保留整项目迁移前置条件，确认复制后自动进入刚才选择的对话，也可以取消自动进入。

项目根球悬浮菜单提供「新建」「复制」「删除」，复制入口不再放在顶部。所有操作使用居中的毛玻璃内置窗口，淡入缩放开启、淡出关闭；窗口不挤占树的宽度，支持 Esc、背景点击关闭和键盘焦点循环。

- **刷新**：发现两端项目、对话，读取原生分支或比较共同历史，更新树索引，不复制原生对话。
- **悬停项目根球 → 复制 → 确认复制整个项目到 DSH**：创建或复用 DSH 工作区，登记已有 DSH 对话，将尚未迁移的 Codex 完整历史写入原生 DSH 对话并登记到项目栏，显示进度和失败项。
- 同一项目同时只运行一个复制任务。重复同步复用 `dshSessionId` 映射，不重复导入。失败后可重试未完成的登记/复制；运行中的 Codex 源对话需先结束或暂停。
- 来源和迁移副本在树中显示为同一个逻辑球，深度相同；新建分支才增加深度。

复制的是对话历史，项目文件仍使用当前本机文件夹。原对话保留；已有副本是迁移时的快照，不覆盖在 DSH 中续聊的内容，也不会自动追加后来在原 Codex 对话产生的消息。

Codex 的完整分页历史转换为 DSH 已完成轮次；工具/推理记录保留为标注后的文本，不重放工具。原始 JSON 存在项目 `.dsh-codex-dots/history/`。附件路径保留，附件二进制不自动搬运，需要时在 DSH 重新附加。

## 加载、缓存与异常记录

页面先读取已有树文件，目录和分支索引在后台完成，进度条显示已比较/总候选数及缓存复用数。分支识别最多 4 路并发，从历史开头读取小页，仅比较用户和助手消息。每对候选发现第一条不同消息就停止后续读取；同一会话被多对比较时共享已读前缀。原生父节点无需内容比较。完全相同的历史可能仍需读到较短一端末尾，才能确定共同前缀长度。

缓存保存于项目 `.dsh-codex-dots/branch-cache.json`，只保存比较结果和源变更标记，不另存完整正文。Codex 用更新时间，DSH 用原生存储文件的大小与修改时间判断是否复用。无稳定标记的活跃会话重新比较。项目列表缓存位于插件 stateDir 的 `library/projects.json`，树仍在项目自身目录。

DSH 启动插件后会排队预载其它项目；主 agent 工作、复制项目或前台索引期间，后台预载让出。后台预载在 DSH 关闭后不运行，重启先显示已有缓存，再检查变化。后台预载不调用模型，不迁移对话。

临时 `selectionchat-temp-*` 记录不纳入项目；后台子代理默认隐藏，可勾选“显示后台子代理”。已消失的记录从视图隐藏；损坏日志单独标记“历史不可用”，复制时跳过并列明。索引不会删除或修写原始历史。用户报告的 wrong Session 属于宿主持久历史校验错误，隔离显示并不代表损坏文件已修复。

DSH 首次打开原生存储时可能仍会执行内部解压/校验；插件使用有限事件窗口，而不调用全量会话接口进行分支比较。明确打开完整历史或复制项目时仍读取完整正文，以保留内容。

## 分支、摘要和 Dots

点击根球新建空白 DSH 对话；点击「分支」填写标题与原因。勾选 DeepSeek 摘要会消耗其额度，摘要显示在连线上。根球面板还可开启项目自动摘要，默认关闭；失败项留在关系面板供手动重试。

父节点规则：**子对话的 `forked_from_id` / `forkedFromId` 优先级最高**。B 的该字段为 A 时，固定为 A → B；两条对话都指向 C 时，保持 C 的两个子分支。它覆盖旧的内容/时间推断及冲突的手动连线；两边继续聊天不会改变方向。该字段含义见 [官方 App Server 分支说明](https://learn.chatgpt.com/docs/app-server#start-or-resume-a-thread)。

插件优先读取本地 rollout 首行 `session_meta`，兼容 `.jsonl`、`.jsonl.zst`、`.jsonl.zstd`；文件名可能包含多个 ID，按元数据中的真实 id 核对。App Server 的 `forkedFromId` 同样作为直接证据。`parent_thread_id` / `parentThreadId` 单独保存为代理委派来源，不能冒充手动分支。

`forked_from_ordinal_exclusive` 原样保存并显示，不等同于界面消息序号。缺少 fork 字段时才使用手动关系、DSH 原生 parentSession 或内容推断；空值和缺失不证明从未分支。已有缓存会在刷新时补录直接证据并纠正旧关系。

缺少来源时比较同一项目、同一平台的用户/助手共同消息前缀，排除短通用问候。先选择共同消息最多、共同字符最多的候选；匹配相同时，选择**创建时间早于当前对话且距离最近**的候选。使用源对话创建时间，不用迁移时间或文件修改时间。标注为「历史＋时间推断」，记录共同消息数和分叉后首条消息 ID；时间也相同或缺失而不能区分时显示待确认，可在「关系」面板修正。

推断关系用于恢复可能的父子结构，不等同于原生 fork 证据。分支摘要采用填写的意图，或分叉附近历史的任务变化。

Dots 已合并到对话球内置窗口，不另设列表或右侧栏。先打开 DSH 主对话，再从 Dots 窗口提交目标或暂停、恢复指令。执行仍遵守费用、计划、权限和额度确认。

历史窗口保留完整 Markdown/代码高亮，正文不按 6000 字截断。树状态每 2.5 秒刷新，历史每 3.5 秒刷新，Dots 状态每秒刷新；暂停后仍刷新已保存历史。迁移不启动模型；摘要、续聊及 Dots 执行会使用相应额度。

## 两端共同维护

项目内 `.dsh-codex-dots/tree.json` 保存原生/推断/手动关系、迁移映射、意图和摘要。DSH 页面、六个树工具和 Codex CLI 共用该文件。`dots_tree` 只刷新索引，整项目复制通过页面按钮执行。

CLI 用法沿用 [2.4.0 文档的“两端共建”说明](conversation-tree.md#dsh-与-codex-共建)，使用真实 ID 登记或关联节点。CLI 不创建会话、不启动模型、不扩大权限。历史及树文件不随发行包发布。

## 手动验收

本次没有使用 Computer Use，没有重启或操作你的 DSH。完成当前任务后，请自行重启 DSH，核对插件 **2.6.10**、组件运行中。

1. 打开「项目对话树」，检查项目球随机散布、数量越多适度越大；点击项目，核对 Codex 项目移到左侧、DSH 移到右侧，中央显示分层树。
2. 鼠标悬停对话球，检查四个小球；打开历史核对长正文、Markdown 和代码颜色。Dots 应只在该窗口出现。
3. 选一个对话少且已结束的测试项目，悬停项目根球，点击「复制 → 确认复制整个项目到 DSH」。完成后返回 DSH 原生项目栏，检查项目及历史；重复同步不应新增重复副本。
4. 再次点击对话球，应直接打开相应 DSH 对话。未复制的项目应先显示整项目复制提示。原 Codex 对话仍在。
5. 重启后再选同一项目，应先出现已存树，未变化的比较显示“复用”；REA 默认应隐藏后台子代理，勾选开关后才能展开它们。核对已知 fork 的原生父节点和深度；历史相同的候选按创建时间选最近较早对话，标注推断。无直接 fork 记录时，手动修改关系后刷新应保留；已有 fork 记录的父节点不可改写，可补充分支原因。
6. 从根新建对话，再建分支和下一层，检查深度 1/2/3。勾选摘要会消耗少量 DeepSeek 额度；未勾选时不调用摘要模型。
7. 如需真实 Dots 联调，先在主对话确认只读目标、最多两轮和额度阈值，再从抽屉提交。暂停后观察状态，明确确认恢复，检查自动刷新及后续派发。不要为验收自行降低阈值。

出现问题时提供操作步骤、报错原文，以及发生在复制前还是复制后。

## 永久删除（两次确认）

悬停项目根球或对话球 → 删除 → 核对数量和范围 →「确认范围，继续」→「再次确认，永久删除」。第一次确认不删除数据，第二次才提交。

- 删除项目：覆盖该项目中登记的 Codex / DSH 对话、后台子代理和迁移副本；调用 DSH 原生 `workspaceRegistry.delete` 移除工作区。项目目录中的代码和文件保留，Codex 桌面自身的项目目录登记不修改。
- 删除对话：删除选定来源及其迁移副本，不级联删除后续分支。分支自身保存的共同历史仍属于该分支。
- Codex 通过 `thread/delete` 删除。DSH 没有永久删除历史 API，先归档阻止继续执行，再由隐藏后台清理进程等到 DSH 完全退出后，删除宿主定位的对应会话目录、插件迁移快照和相关全文检索记录。这不是把归档当成删除；界面明确显示「待退出后删除」。
- 清理状态记录于界面给出的 `stateDir/library/deletions/<任务>.json`。完全退出 DSH 后，用 PowerShell 查看该文件：`Get-Content -LiteralPath '界面给出的完整路径' -Raw`。`status` 为 `completed` 后再启动 DSH；`error` 时查看 `errors`，不能当作已完成。请勿在清理完成前重启 DSH。
- 仍由 Dots 代管或正在执行的 DSH 对话需要先结束任务。删除失败会显示错误，未删除部分保留。后台发现依据删除记录过滤，刷新不会复活节点。

手动验收请新建可丢弃的测试项目和两条短对话：检查原生直接进入、根球复制入口、居中窗口和两次删除确认。取消第一次或第二次确认时，对话应仍存在。确认删除其中一条，完全退出 DSH，核对结果文件完成后重开；另一条对话和项目文件应仍在。这里的删除是用户明确要求的永久删除，安装测试不会自动操作实际历史。

## 空白与异常记录（2.6.10）

星图默认只计入可浏览的普通对话。只有初始化事件的未命名 DSH 会话、历史读取已失败的会话不显示为普通球；勾选“显示空白/异常”可查看诊断节点。空白判断必须读到短页末尾，不能仅因第一页没看到消息就推定整段历史为空。文件未变时复用空白结果，新消息写入后重读并重新显示。

RACDL 的 `session-aa7b9807…` 是仅含权限/沙箱/种子结束记录的空白会话；`session-382f88fb…` 是已归档分支，其中投递标记仍指向父 Session，导致宿主校验失败。本修复处理列表展示和计数，不修改或删除这两份原始日志，也不声称已修复其历史格式。

请完全退出 DSH 后重开，在插件管理确认版本 `2.6.10`，打开 RACDL 并点刷新：在当前已核对的数据中，默认应显示 1 个普通对话，开启诊断开关后可看到另外两个记录。若仍看到旧版右侧面板，说明客户端模块尚未重新加载；本机插件登记已确认指向此源码目录。

## 分支摘要、返回与接口更新（2.6.10）

创建分支时勾选 DeepSeek 摘要，短摘要调用会关闭思考模式并使用 512 token 输出预算；主对话的模型设置保持原值。成功创建分支后，窗口直接关闭并更新树，不显示继承历史，也不自动打开新对话。若摘要请求失败，分支仍保留，页面明确显示“分支已创建，摘要未完成”，可以在该节点的关系窗口重新生成。

顶部“← 返回”依次退出操作窗口、项目树、星图；窗口内“← 返回项目”只关闭窗口。返回不发送对话指令。

`not found` 是宿主未注册该 URL 时的纯文本响应。新版会检查后端删除能力，并正确显示 HTTP 错误，不再对纯文本盲目执行 JSON 解析。更新后需要完全退出 DSH 再启动，让前端和宿主端共同加载 2.6.10；若页面提示后端尚未重载，不会继续提交删除。删除仍需两次确认。

手动验收：完全退出并重开 DSH，在插件管理确认版本 2.6.10；选择测试对话创建分支并勾选摘要（会使用少量 DeepSeek 额度），确认窗口关闭、树出现新分支及简短原因；分别检查窗口和顶部返回按钮。删除测试只使用可丢弃的对话，先检查确认范围和两步确认是否正常显示。

## 提醒与自适应窗口（2.6.10）

提醒在画布下方居中悬浮，显示 5 秒后自动收起。同一条错误、同一删除任务的同一状态不会因轮询重新弹出；有新的状态或内容时重新提示。正在进行的索引和复制进度仍更新到任务结束。收起提醒不取消后台任务，也不更改删除状态。

操作窗口按实际内容决定高度，短表单不再撑满页面；长历史达到窗口可用高度上限后内部滚动。提醒层不会改变画布宽高，工作区和画布有固定节点标识，避免通知数量变化导致尺寸监听失效。

手动验收：完全退出并重开 DSH，在插件管理确认版本 2.6.10。观察已有提醒是否约 5 秒后收起，等待 10 秒轮询后不应再次出现；提醒显示与消失时项目球应保持位置。分别打开复制、分支、长历史窗口，检查短内容收缩和长历史内部滚动。

## 鼠标操作（2.6.10）

操作小球只在鼠标位于根球/对话球及其操作区域时显示，离开后收回；点击操作后留下的键盘焦点不会继续展开菜单。

单击对话球只显示“再次点击进入对话”，不会打开原生对话或迁移窗口；在同一球上快速双击才进入。DSH 原生对话直接打开，Codex 未完成迁移时双击后仍进入迁移确认流程。项目球展开和根球新建入口保持原操作。

提醒层位于画布底部居中，不占布局空间。单击提示显示约 5 秒，双击进入时立即清除。请重启 DSH 后检查：创建分支并移开鼠标时操作小球收回；单击只在底部提示、快速双击进入。

## 简化顶部与搜索（2.6.10）

页面不再显示标题、副标题/版本号及底部操作说明。长条搜索框位于中央，输入实时筛选项目名称，不区分大小写、忽略首尾空格；从项目树输入搜索会回到项目结果，清空后恢复全部项目。没有结果时显示“没有匹配的项目”。

全部项目、居中、刷新和返回合并到右侧，返回位于最右端并用更明显的底色与字重显示。窄窗口改为搜索和操作两行。更新后完全退出并重开 DSH，版本可在插件管理中核对为 2.6.10，无需再寻找页面副标题。

## 连贯动态显示（2.6.10）

项目球在主页、树根、左右侧栏之间使用相同的路径标识。操作前记录可见位置，随后用约 520ms 的移动、缩放和交叉淡化衔接新位置；退出搜索结果的球分别向左右边缘移出。代理层不接受点击，动画完成后删除，不留下重复球。

快速修改搜索词时，下一段动画接续当前过渡位置；清空搜索后项目球移入并重排。项目根在目录加载前就显示，子对话加载后再进入。项目球自身的轻微悬浮与位置移动分开处理，避免互相覆盖。

内置窗口采用约 360ms 向上移入、240ms 向下移出并淡化。窗口打开时切换项目会先关闭窗口再展开项目；原有自适应高度、滚动和焦点恢复继续保留。系统启用“减少动态效果”时跳过位移动画。

手动验收：更新并重启 DSH 后，连续输入、删除搜索词，观察球群移动和出入；打开项目、切换左右项目、返回全部项目；在过渡尚未结束时再操作，确认球不会跳回起点、残留或误触。再检查窗口的移入、返回关闭及 Esc 关闭。此版本通过离线几何与动画协议测试，未使用 UI 自动化；实际流畅度由本机界面验收。


## 动画开销与入口整理（2.6.10）

移除原生对话页右上角的重复入口，统一从左侧“项目对话树”进入。快照不再克隆所有球，只有需要移动且出发或到达位置在画面内的球创建代理；未变化和屏幕外球直接保留最终布局。200 球离线场景只有 1 球可见并移动时，仅创建 1 个代理。位移期间暂停背景模糊和连线动画，结束后恢复毛玻璃；弹窗显示时暂停被遮挡的背景动画。

手动验收：完全退出并重开 DSH，在插件管理核对 2.6.10；检查原生聊天右上角不再出现“对话树”。从左侧入口连续搜索、清空、展开和退出项目，检查移动连续性；在动画途中再次切换，检查是否有残留球。打开历史和分支小窗，检查进出动画。离线测试验证工作量和动画衔接，实际帧率需在本机界面观察。
