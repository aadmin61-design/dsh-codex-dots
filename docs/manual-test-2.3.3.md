# 2.3.3 手动验收（DSH 0.2.1-rc.3）

代码和非界面测试已完成。以下操作由用户在 DSH 执行；本次更新没有自动重启应用或调用模型。

## 启用与只读界面检查

1. 等当前 DSH 任务结束，退出并重新打开 DSH。现有本地链接已指向更新后的目录；其他电脑需要先解压新 ZIP 并替换原插件文件。
2. 打开「插件」→ `@local/dsh-codex-dots`，核对版本 **2.3.3**、组件「运行中」。若显示已停用，重新启用；不需要点击版本豁免或接受不兼容风险。
3. 在既有 DSH 主对话中点击「Codex」，选择一个已有 Codex 对话。确认正文、Markdown 表格、代码颜色和「原文 / 完整记录」可见，而非只有 DONE。
4. 若有更早内容，点击「加载更早消息」或「加载全部历史」。只浏览列表和历史不会启动 Codex 模型轮次。

如有错误，请反馈出错步骤、插件版本以及完整错误文本。

## 可选：DeepSeek 子对话两轮测试

这部分会消耗 DeepSeek 额度。仅在你决定进行真实联调时执行；无需运行 Codex、命令或实验。

在一个已选择 DeepSeek、已设置工作目录的主对话发送：

> 使用 codex-dots 做最多两轮的轻量测试。只创建一个 backend=deepseek 的只读子角色，目录继承当前主对话；不调用工具、不读写文件、不执行命令、不运行实验。第一轮只回复 READY，收到后暂停整个任务并等我确认恢复；恢复后使用新 decisionId 给同一个子对话派发第二轮，只回复 DONE，然后验收结束。先给计划，按原生流程确认费用和计划。保留当前预算、权限和所有确认边界。

预期结果：

- 费用及计划确认后创建子对话，主对话结束当前回复；子对话输出后主对话收到阶段通知。
- READY 后任务暂停，不自动开始第二轮。
- 你发送「恢复此测试，继续第二轮」并完成恢复确认后，主代理实际调用 `dots_dispatch`，仍使用同一子对话 ID。
- DONE 后验收结束，恰好两轮，无命令或实验执行。

若未继续，请反馈最近的 `dots_status` 输出及错误文本；不要反复重启任务或提高预算。
